# Real Chromium extension smoke testing

This suite tests the locally packaged Manifest V3 build without external ad services. It does **not** establish broad, real-site blocking performance.

## Run

- Use Node.js 22.
- Run `npm ci --no-audit --no-fund` to install the locked `playwright` development dependency and its integrity-checked dependency tree.
- Run `npm run build`.
- Run `npx playwright install --with-deps chromium` (Linux CI; on your OS use `npx playwright install chromium`).
- Run `npm run test:e2e`.

The test launches Playwright's **bundled Chromium** with a temporary persistent profile, explicitly side-loads `dist/chrome`, binds its synthetic HTTP fixture to `127.0.0.1`, and maps reserved `.test` hostnames to loopback. No public ad websites or personal browsing records are used. Logs record the Node and Chromium versions.

### Evidence checked
- Extension MV3 service worker starts and settings page loads.
- Bundled DNR blocks the designated fake ad resource and allows a benign control image.
- Disabling protection allows the fake ad resource and restores cosmetic element.
- Per-site exception allows the fake ad after page reload; removal restores blocking.
- Reopening a persistent Chromium profile retains trusted-site settings.
- A legitimate non-ad element remains visible.
- Subdomains inherit a trusted-site exception; similarly named unrelated domains do not.
- Every case checks server request counts; blocked cases require Chromium's `ERR_BLOCKED_BY_CLIENT`, so a generic network failure cannot pass as blocking.
- Network and cosmetic behavior, including global pause, are checked after Chromium restarts.
- Node tests cover pending checkbox edits and recovery from rejected settings writes in both popup and options.

### Limits
- Tests do **not** yet cover third-party filter-list parsing, Chrome Web Store distribution, MV3 release-mode statistics, or millions of real ads.
- Chrome and Edge stable no longer support the command-line extension flags required by this workflow; test with Playwright's `chromium` channel as documented by Playwright.
- If the smoke test fails in cloud CI, preserve failure logs and fix fixture/extension issues rather than claiming browser verification.
- The first test runs locally on loopback with custom hostname resolution. It makes no network connections to actual ad networks.

## Reproducibility and dependency scope

`package-lock.json` was generated by npm in [CI run 43646726195](https://github.com/renoukhan39-bit/ad-blocker/actions/runs/43646726195), then committed for clean `npm ci` validation. It pins Playwright and playwright-core to 1.65.0 with registry integrity hashes; both declare Apache-2.0 in their package metadata. They are development dependencies only. The extension build copies only the original extension folders and does not package Node dependencies. This does not select or change the product's source license.

The development workspace can run Node checks and packaging. Its npm egress denial and Chromium socket denial prevent local browser validation; CI is the browser evidence source until that environment is changed. Successful earlier CI is not evidence for later commits: inspect the run on the final PR head before merging.
